§01Overview and architecture

Gage Cloud is a proposed cloud gauge registry where every caliper, torque tool and probe has a live record. BLE tags on tool cases update "last seen", calibration due dates feed work orders, and Digital Clipboard blocks a reading from an overdue gauge. Studies (GR&R, bias, linearity, stability) run on collected data, and certificates are stored with each event. It is the concept successor to DataMyte's EnGagePlus! (see §12).

What it does

  • Keeps a registry of gauges with calibration history and certificates.
  • Schedules calibrations and feeds work orders to labs.
  • Runs GR&R (ANOVA), bias, linearity and stability studies.
  • Tracks location with BLE tags and gateways.
  • Blocks readings from overdue or quarantined gauges in Collect Edge and Digital Clipboard.

Architecture

Data flows left to right. Every write passes schema validation at ingest, lands in the tenant data plane with an immutable audit entry, and is exposed to apps, BI and agents through the same API. Anything an agent proposes comes back as a draft that a named person approves.

§03Getting started

Proposed The quickest path from an empty tenant to a first live result.

Five steps

  1. Import gauges (CSV or EnGagePlus! export) and reconcile IDs.
  2. Set calibration intervals and procedures per gauge type.
  3. Tag high-risk tools (torque wrenches, master gauges) and place gateways.
  4. Upload the latest certificates.
  5. Turn on lockout so overdue gauges cannot record readings.

First API call

Create a service client in Admin → Integrations, exchange its secret for a token, then call the API.

# 1. token (OAuth 2.0 client credentials)
curl -s -X POST https://auth.concept.example/oauth/token \
  -d grant_type=client_credentials -d client_id=$CLIENT_ID -d client_secret=$CLIENT_SECRET \
  -d scope="gage.read gage.write"
# 2. first call
curl -s https://acme.api.concept.example/v1/gage/gauges?due_within=30d -H "Authorization: Bearer $TOKEN"

Response (shape):

{
  "items": [
    {
      "id": "gag_prb0001",
      "name": "4-point probe 1",
      "due": "2026-10-30",
      "status": "in_service",
      "last_seen": "Lab shelf 2"
    }
  ]
}

§06REST API reference

Proposed REST over HTTPS, JSON bodies, base URL https://{tenant}.api.concept.example/v1. Every endpoint below is a design proposal; none is live.

Authentication

  • OAuth 2.0 client credentials for services; authorization code + PKCE for users; tokens are JWTs valid 15 minutes.
  • Scopes per product and verb: gage.read gage.write gage.approve. Plant-level claims restrict data to the plants granted.
  • Writes that change a released record (limits, plans, calibrations) require a user token and create a draft unless the user holds the approver role.

Draft and approval flow

  1. Agent calls a write tool; the server validates input and stores a draft with the evidence links.
  2. The owner gets a notification (Escalate, email or mobile push).
  3. A person with the approver role accepts, edits or rejects; acceptance applies the change and signs it (see §10).
  4. The agent receives the outcome by push notification or polling GET /drafts/{id}.

Read with care: the five check-standard wafers were chosen to span 94.3–101.1 Ω·cm, so part-to-part variation is much larger than in a production sample; %GRR and ndc look excellent for that reason. The study has no tolerance, so no %GRR-of-tolerance is given (as on the screen).

The Methods page and the concept screen report the NIST handbook's own breakdown: repeatability 0.0932 Ω·cm pooled from the 6 short-term repeats inside each daily measurement, day-to-day 0.0214, probe-to-probe 0.0212. The ANOVA above works on the daily averages, so its "repeatability" (0.0437) is a different quantity; both are shown so the difference is explicit.

Stability and calibration intervals

Check-standard readings over time go on an individuals chart (same formulas as SPC Stream); a signal triggers a calibration work order. Interval adjustment (proposed): lengthen by 25% after three consecutive in-tolerance calibrations, shorten by 50% after any out-of-tolerance result, bounded by the customer's procedure.

§09Integrations

Proposed Integration points. Vendor names are typical targets, none confirmed as partners.

OPC UA

The edge gateway runs an OPC UA client (Security Policy Basic256Sha256, Sign&Encrypt). Subscriptions map node IDs to characteristics; sampling interval and deadband are set per node.

# not typical; gauges report via Collect Edge or lab uploads

MQTT (Sparkplug B)

Gateways publish to the tenant broker over TLS 8883. Topic namespace spBv1.0/{group}/DDATA/{edge_node}/{device}; birth/death certificates mark devices online and offline.

spBv1.0/plantA/DDATA/gw-crib/ble-7f21
{"timestamp":1760806931000,"metrics":[{"name":"rssi","datatype":"Int32","value":-61},{"name":"zone","datatype":"String","value":"Quarantine bin"}]}

MES / ERP

ERP supplies asset numbers; calibration lab systems connect by CSV or API. Outbound webhooks push events; inbound REST accepts part, order and serial context so every result carries genealogy.

Power BI and BI tools

Due, overdue and study tables are available to BI. A read-only OData v4 feed (/v1/odata/gage) exposes curated tables with row-level security inherited from the user's token; scheduled refresh uses a service principal.

Data protection

  • Per-tenant schema plus PostgreSQL row-level security; plant claims in every token.
  • Encryption: TLS 1.2+ in transit; AES-256 at rest; customer-managed keys (KMS) on enterprise plans.
  • Backups: point-in-time recovery 35 days; encrypted, region-pinned.
  • Retention: configurable per record type; legal hold blocks deletion.

§12Migration from the legacy product

The legacy product, as DataMyte describes it

Cited DataMyte describes EnGagePlus! as gauge and tool automation software: calibration records and history, tool-crib check-in/out, reports for due, overdue and out-of-tolerance gauges, certificates and location, and built-in Gauge R&R (standard or ANOVA), bias, stability and linearity studies. The page does not state a deployment model or system requirements. Sources: EnGagePlus! (pages read Oct 17, 2026).

Migration path

Proposed

  1. Export EnGagePlus! gauge records and history.
  2. Import into the registry and reconcile IDs.
  3. Tag the highest-risk tools first (torque wrenches, master gauges).
  4. Switch scheduling and certificates to the cloud.
