§01Overview and architecture

Plan Copilot is a proposed FMEA and control-plan editor with a copilot side panel. It drafts failure modes, causes and controls from the process flow, flags weak detection ratings, and uses live inspection, SPC and torque results to suggest Occurrence and Detection updates. Every change is a draft an engineer approves. It is the concept successor to DataMyte's QPS PRO / Quality Planning Studio (see §12).

What it does

  • Edits process flows, PFMEA, DFMEA and control plans with version control.
  • Supports AIAG 4th Edition RPN and AIAG & VDA action priority (tenant-loaded tables).
  • Links control-plan rows to live characteristics and checklists.
  • Drafts failure modes, reaction plans and O/D changes with evidence.
  • Exports PPAP packages.

Architecture

Data flows left to right. Every write passes schema validation at ingest, lands in the tenant data plane with an immutable audit entry, and is exposed to apps, BI and agents through the same API. Anything an agent proposes comes back as a draft that a named person approves.

§03Getting started

Proposed The quickest path from an empty tenant to a first live result.

Five steps

  1. Import a process flow or start from a template.
  2. Generate PFMEA rows from the flow; review the drafts.
  3. Load your AIAG & VDA rating and AP tables in Admin → Rating tables.
  4. Link control-plan characteristics to SPC Stream and checklists to Digital Clipboard.
  5. Release the FMEA; future changes become drafts with approvals.

First API call

Create a service client in Admin → Integrations, exchange its secret for a token, then call the API.

# 1. token (OAuth 2.0 client credentials)
curl -s -X POST https://auth.concept.example/oauth/token \
  -d grant_type=client_credentials -d client_id=$CLIENT_ID -d client_secret=$CLIENT_SECRET \
  -d scope="plan.read plan.write"
# 2. first call
curl -s https://acme.api.concept.example/v1/plan/pfmeas?part=seat-frame -H "Authorization: Bearer $TOKEN"

Response (shape):

{
  "items": [

      "part": "Seat frame",
      "revision": "C",
      "rows": 4,
      "open_drafts": 2,
      "standard": "AIAG-VDA 2019"

§06REST API reference

Proposed REST over HTTPS, JSON bodies, base URL https://{tenant}.api.concept.example/v1. Every endpoint below is a design proposal; none is live.

Authentication

  • OAuth 2.0 client credentials for services; authorization code + PKCE for users; tokens are JWTs valid 15 minutes.
  • Scopes per product and verb: plan.read plan.write plan.approve. Plant-level claims restrict data to the plants granted.
  • Writes that change a released record (limits, plans, calibrations) require a user token and create a draft unless the user holds the approver role.

Draft and approval flow

  1. Agent calls a write tool; the server validates input and stores a draft with the evidence links.
  2. The owner gets a notification (Escalate, email or mobile push).
  3. A person with the approver role accepts, edits or rejects; acceptance applies the change and signs it (see §10).
  4. The agent receives the outcome by push notification or polling GET /drafts/{id}.

§08Statistics and methods

Plan Copilot supports both AIAG 4th Edition (RPN) and AIAG & VDA FMEA Handbook (2019) action priority. PFMEA rows here are Sample; the control-plan capability result is Real dataset.

Risk priority number (AIAG 4th Edition)

RPN=S×O×D,S,O,D∈{1,…,10},1≤RPN≤1000
Step (sample)Failure modeSODRPNAP shown
10 Weld bracket to frameIncomplete fusion945180H
20 Torque seat-belt anchorUnder-torque1034120H
30 Install reclinerMissing clip63354M
40 Paint frameThin coating54480L

RPN ranks step 10 (180) above step 20 (120), although step 20 has severity 10. That is the known weakness of RPN: equal weights for S, O and D.

Action priority (AIAG & VDA, 2019)

AP replaces RPN with a lookup over (S, O, D) that weights severity first, then occurrence, then detection, and returns High, Medium or Low. Plan Copilot evaluates AP from the customer's licensed AIAG & VDA rating and AP tables, loaded per tenant; the handbook tables are copyrighted and are not reproduced here.

AP=f(S,O,D)∈{H,M,L},f = tenant-loaded table

Validation rules (proposed): AP = H requires an action owner and due date; any S ≥ 9 row needs a documented prevention control; changing S on a released FMEA requires approver sign-off.

Evidence-based O and D suggestions

The copilot links control-plan rows to live data and proposes rating changes as drafts. Mapping from evidence to ratings is an organization-defined table (examples below are placeholders, not AIAG-VDA values).

EvidenceExample rule (tenant-defined)Draft suggestion
Residual torque audit: 2 under-torque anchors this week (sample)≥ 1 confirmed failure per week → O +1Raise O 3 → 4 on step 20, add gauge-calibration check
Capability on linked characteristicCpk ≥ 1.33 sustained 25 subgroups → consider lower OShow Cpk with evidence link
No reaction plan in control plan rowMissing fieldDraft reaction plan text

Worked link, Montgomery piston rings via the qcc R package: the demo control-plan row "piston ring inside diameter, 74.000 ± 0.050 mm, X̄–R n = 5" pulls the live result Cp 1.70, Cpk 1.66, with subgroups 37, 38, 39 above the UCL — an out-of-control signal that should block any O reduction until explained.

Cpk=min(74.05−74.0012,74.0012−73.95)3×0.009785=1.66

Copilot guardrails

  • Every suggestion is a draft with evidence links; nothing changes a released FMEA without an engineer's approval.
  • Suggestions cite their inputs (inspection IDs, audits, characteristics).
  • The model never lowers severity; S changes are human-only.

§09Integrations

Proposed Integration points. Vendor names are typical targets, none confirmed as partners.

OPC UA

The edge gateway runs an OPC UA client (Security Policy Basic256Sha256, Sign&Encrypt). Subscriptions map node IDs to characteristics; sampling interval and deadband are set per node.

# not typical for Plan Copilot; evidence arrives via SPC Stream and Torque Insight APIs

MQTT (Sparkplug B)

Gateways publish to the tenant broker over TLS 8883. Topic namespace spBv1.0/{group}/DDATA/{edge_node}/{device}; birth/death certificates mark devices online and offline.

# evidence events consumed from the tenant bus
spc.alarm.opened {"characteristic_id":"chr_01JB2Y","rule":"we1"}

MES / ERP

PLM import for part/BOM; MES/ERP for part status. Outbound webhooks push events; inbound REST accepts part, order and serial context so every result carries genealogy.

Power BI and BI tools

FMEA, AP distribution and open-draft tables are available to BI. A read-only OData v4 feed (/v1/odata/plan) exposes curated tables with row-level security inherited from the user's token; scheduled refresh uses a service principal.

Data protection

  • Per-tenant schema plus PostgreSQL row-level security; plant claims in every token.
  • Encryption: TLS 1.2+ in transit; AES-256 at rest; customer-managed keys (KMS) on enterprise plans.
  • Backups: point-in-time recovery 35 days; encrypted, region-pinned.
  • Retention: configurable per record type; legal hold blocks deletion.

§12Migration from the legacy product

Migration path

Proposed

  1. Import existing QPS databases (DataMyte already offers bulk import of control plans and PFMEAs).
  2. Run the copilot read-only on imported documents.
  3. Turn on draft suggestions for one product line.
  4. Move document control to the cloud tenant or keep it on-prem.
